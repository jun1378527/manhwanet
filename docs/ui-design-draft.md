> **상태: 방향 A "종이 서가" 확정(#32), 프론트엔드 적용 진행 중(#33).** 적용 결과와 시안과의 차이는 §8에 기록합니다. 아래 §1~§7은 확정 전 초안 내용 그대로입니다.
> 기준 커밋: `a50d482` (작업 트리의 미커밋 로그인 보호 명세는 그대로 둠)

- 시각 시안

## 1. 현재 화면 진단 [사실]

| 항목 | 현재 |
|---|---|
| 글꼴·색 | 시스템 글꼴(`system-ui`, Malgun Gothic, Noto Sans KR/JP), 흰 바탕 + 파란 강조(`#1f5fd1`), 다크 모드 지원, 포커스 `#f2a900` |
| 목록 `/works` | 한 열 카드: 대표 제목, 형식 배지, 작가 크레딧, 평균 별점·참여자 수, 페이지 이동 |
| 상세 `/works/[id]` | 순서: 제목·형식 → 대표 제목 언어·국가 → 별점 → 리뷰 → 작가 → 다른 제목 → 줄거리 |
| 별점 | 0.5~5.0, 0.5 단위 10개 라디오. 평균은 소수 한 자리, 참여자 수 |
| 리뷰 | 1인 1개, 10~2,000자, 스포일러 표시(펼치기 전 본문 미렌더링), 수정·삭제 충돌 시 최신 리뷰와 비교 선택 |
| 로그인·가입 | 단일 폼, 필드별 오류, 429 시 남은 시간 안내 |
| 쓸 수 있는 데이터 | 형식(웹툰·페이지 만화), 국가, 대표·다른 제목(언어 코드), 줄거리, 작가 역할(글·그림·원작), 별점 평균·참여자 수, 리뷰 목록(닉네임·작성·수정 시각·수정 여부·스포일러), 내 별점·내 리뷰 |
| 없는 데이터 | 표지, 장르·태그, 연재 상태·연도, 별점 분포, 검색·정렬·필터, 목록의 리뷰 수, 리뷰 작성자의 별점 |

문제점
- 상세 페이지에서 작품 정보(작가·줄거리)가 평가 아래로 밀려, 처음 보는 작품을 이해하기 전에 평가 영역부터 보입니다.
- 리뷰 본문이 화면 너비 전체로 늘어나 긴 글을 읽기 어렵습니다(한 줄 길이 제한 없음).
- 모바일에서 별점·리뷰 작성 요소가 본문 중간에 있어 엄지로 닿기 어렵고, 10개 라디오가 한 줄에 몰립니다.
- 표지가 없어 목록이 글자 위주로 단조롭습니다.

## 2. 디자인 방향

### 방향 A "종이 서가" (권장)

| 항목 | 내용 |
|---|---|
| 분위기 | 책장에 꽂힌 독서 노트. 차분하고 오래 읽기 편한 화면 |
| 색 | 바탕 `#F6F5F1`(옅은 종이), 면 `#FFFFFF`, 먹 `#1D1C1A`, 행동 `#2B4C9B`(책갈피 청), 페이지 만화 타일 `#7D3520`(인주), 별 `#A8701A` |
| 글꼴 | 제목 Noto Serif KR·JP 700 / 화면 글자 Noto Sans KR·JP 400·600 / 리뷰·줄거리 본문 Noto Serif KR 17px, 행간 1.85 |
| 형태 | 모서리 10px, 1px 선, 아주 옅은 그림자 |
| 장점 | 긴 리뷰·줄거리 가독성이 가장 좋음. 표지가 없어도 타이포만으로 완성도가 남. 한국어·일본어 제목이 같은 세리프 계열로 어울림 |
| 단점 | 세리프 한글 웹폰트는 용량이 큼(부분 글꼴·`display: swap` 필요). 목록을 빠르게 훑는 느낌은 B보다 약함. 제목과 본문 글꼴이 둘이라 규칙 관리가 필요 |

### 방향 B "컷 그리드"

| 항목 | 내용 |
|---|---|
| 분위기 | 만화 칸처럼 굵은 테두리와 또렷한 대비. 경쾌하고 빠른 화면 |
| 색 | 바탕 `#FFFFFF`, 먹선 `#111111`, 행동 `#1736D9`(신호 청), 강조 면 `#FFF1A6`(형광), 경고 `#A33600` |
| 글꼴 | 제목 Gothic A1 800 / 화면·본문 IBM Plex Sans KR 400·600 (일본어 Noto Sans JP) |
| 형태 | 모서리 4px, 2px 검은 선, 4px 오프셋 그림자 |
| 장점 | 목록 비교·탐색이 빠름. 모바일에서 버튼·칸 구분이 매우 분명함. 대비가 높음(본문 18.9:1) |
| 단점 | 굵은 선과 그림자가 긴 리뷰 읽기에서 시선을 분산시킴. 다크 모드에서 먹선 규칙을 다시 설계해야 함. 강한 스타일이라 기능이 늘수록 화면이 복잡해 보이기 쉬움 |

### 권장: A

서비스의 핵심이 "작품 정보와 독자 평가를 읽기 쉽게, 긴 리뷰를 편하게"이므로 A를 권장합니다. B에서는 **모바일 하단 행동 바와 칸 구분이 분명한 별점 선택**만 A에 맞게 가져왔습니다(시안에 반영).

## 3. 화면 시안

### 3.1 작품 목록 (데스크톱·모바일)

- [디자인] 카드
  - 왼쪽에 **표지 대체 타일**(제목 첫 글자 + 형식 색)을 둡니다.
  - 오른쪽에 제목(언어 `lang` 지정), 형식·국가, 역할별 크레딧, `★ 평균 · N명 참여`를 둡니다.
  - 평가가 없으면 "아직 평가가 없습니다"를 씁니다.
- [디자인] 데스크톱은 2열 격자(최소 480px), 모바일은 1열입니다. 모든 링크·버튼은 44px 이상입니다.
- [디자인] 상단에 서비스 한 줄 소개와 "전체 N개 · 현재/전체 페이지"를 둡니다.
- 넣지 않은 것: 검색·정렬·장르 필터·랭킹(데이터·API 없음). 자리도 만들지 않았습니다.

### 3.2 작품 상세 (데스크톱)

- [디자인] **정보 → 평가 순서로 재배치**합니다.
  - 머리: 큰 타일, 형식·국가 배지, 대표 제목, 다른 제목 1개, 크레딧, 평균·참여자·리뷰 수 링크
  - 본문: 줄거리, 다른 제목·언어·국가, 리뷰
- [디자인] 오른쪽 열에 **독자 평균 별점**(큰 숫자 + 별 + 참여자 수)과 **내 별점** 카드를 둡니다. 화면 폭이 좁으면 아래로 내려갑니다.
- [디자인] 리뷰
  - 본문은 세리프 17px·행간 1.85, 한 줄 최대 38em(약 36~40자)입니다.
  - 6줄을 넘으면 접고 "전체 펼치기"를 둡니다.
  - 내 리뷰는 목록 위 별도 상자에 두고 수정·삭제 버튼을 붙입니다.
  - 스포일러 리뷰는 주의 색 상자와 "내용 보기"로 둡니다(현재처럼 펼치기 전 본문 미렌더링).
- [데이터 있음] 리뷰 수는 공개 리뷰 목록 응답의 `totalElements`로 표시할 수 있습니다(상세는 이미 리뷰 목록을 함께 불러옴).
- 넣지 않은 것: 별점 분포 그래프(API 없음), 리뷰 작성자의 별점(리뷰·별점이 독립이라 응답에 없음), 리뷰 정렬·좋아요.

### 3.3 작품 상세·별점·리뷰 (모바일)

- [디자인] 상세 상단에 평균·참여자 카드와 "내 별점 4.5 · 별점 바꾸기"를 둡니다.
- [디자인] **하단 행동 바**: [별점] [리뷰 쓰기/내 리뷰 수정]. 엄지 영역에서 바로 작성할 수 있습니다.
- [디자인] **별점 시트**: 0.5~5.0을 5×2 격자 버튼(각 44px 이상)으로 둡니다.
  - 선택값을 큰 숫자와 별로 미리 보여 주고, 저장된 값은 테두리로 구분합니다.
  - 버튼 이름은 "4.0점으로 변경"처럼 결과를 말합니다.
- [디자인] **리뷰 작성 화면**(전체 화면)
  - 본문 입력은 읽기와 같은 글꼴로 씁니다. 글자 수 표시(10~2,000자)와 스포일러 체크·설명을 둡니다.
  - 저장·취소는 하단 바에 둡니다.
- [디자인] **충돌 안내**: 기존 문구와 선택지(덮어쓰기·최신 리뷰로 바꾸기)를 유지합니다. 최신 리뷰를 카드로 보여 주고 두 버튼을 세로로 쌓아 오탭을 줄입니다.
- 같은 자리의 다른 안내: 저장 완료, 로그인 만료(작성 중인 글 유지), 반영 여부 모름.

### 3.4 로그인·가입

- [디자인] 같은 카드·입력·버튼 규칙을 씁니다. 데스크톱은 가운데 카드, 모바일은 전체 폭입니다.
- 상태별 안내
  - 401 `INVALID_CREDENTIALS`
  - 429(남은 시간)
  - **503 `AUTH_BUSY`(#28 구현 후, 과부하)**
  - 연결 실패
  - CSRF 실패
- [디자인] 가입: 이메일 중복 오류를 칸 아래에 붙입니다. 비밀번호 규칙과 현재 글자 수를 보여 주고, 제출 중에는 "가입하는 중…"으로 표시합니다.

### 3.5 표지: 현재와 향후

| | 현재 (지금 가능, [디자인]) | 향후 ([데이터·API]) |
|---|---|---|
| 목록·상세 | 제목 첫 글자 + 형식 색 타일(장식, `aria-hidden`) | 2:3 표지 이미지. 실패·미등록이면 대체 타일로 돌아감 |
| 필요한 것 | 없음 | 표지 필드·등록 API, **이미지 사용 권리와 출처 표기**, 저장·크기 변환·캐시, 대체 텍스트 규칙 |

시안의 향후 화면은 빗금 표시 "표지 이미지 자리"만 보여 주며 실제 표지가 아닙니다.

## 4. 공통 규칙 (방향 A 기준, B 값은 시안 Tweaks 참고)

| `--bg` | `#F6F5F1` | `#161513` | 바탕 |

대비(계산값, WCAG)
- 본문 15.6:1, 보조 글자 6.3:1(바탕)·6.9:1(면), 링크·행동 8.1:1
- 주의 6.9:1, 오류 5.9:1, 저장 완료 5.8:1, 다크 본문 15.3:1·보조 8.0:1
- 포커스 테두리 4.2:1. 현재 앱의 `#f2a900`은 흰 바탕에서 3:1에 못 미쳐 바꿉니다.
- 별 색(4.2:1)은 장식이고 점수는 항상 숫자로 함께 씁니다.

### 4.2 타이포

| 역할 | 크기·행간 | 글꼴(A) |
|---|---|---|
| 작품 제목 | 34px(모바일 26~28) / 1.25 | 세리프 700 |
| 섹션 제목 | 22px(모바일 20) / 1.35 | 세리프 700 |
| 카드 제목 | 19px(모바일 17) / 1.35 | 세리프 700 |
| 화면 본문 | 15px / 1.6 | 산세리프 400 |
| 리뷰·줄거리 | 17px / 1.85, 최대 38em | 세리프 400 |
| 보조·캡션 | 13px / 12px | 산세리프 |

- 한국어는 `word-break: keep-all`(현재와 같음)을 씁니다. 일본어 제목·이름은 `lang="ja"`로 표시하고 JP 글꼴로 대체합니다.
- 웹폰트를 쓸 때는 부분 글꼴과 `font-display: swap`을 쓰고, 실패하면 시스템 글꼴로 대체합니다(§7 결정 D-3).

### 4.3 간격·형태

- 4의 배수: 4·8·12·16·24·32·48
  - 카드 안쪽 16~20, 섹션 사이 32~40, 페이지 좌우 여백 데스크톱 24·모바일 16
- 콘텐츠 최대 폭 1,120px(현재 960px)
- 모서리 10px(작은 요소 6px), 선 1px

### 4.4 버튼·입력·포커스

- 버튼: 기본(채움), 보조(테두리), 텍스트, 삭제(빨간 테두리). 높이 44px 이상(작은 버튼 36px은 데스크톱 보조 행동에만).
  - 비활성: 투명도 45%, 커서 금지
  - 처리 중: 비활성 + "저장 중…" 문구(스피너는 장식)
- 입력: 높이 48px, 16px 글자(모바일 확대 방지)
  - 오류: 빨간 테두리 + 옅은 면 + 칸 아래 문구(`aria-invalid`, `aria-describedby`)
  - 글자 수: 칸 아래 오른쪽
- 포커스: 모든 대화형 요소에 3px `--focus` 외곽선, 2px 간격(`:focus-visible`). 하단 시트는 열릴 때 제목으로, 닫힐 때 연 버튼으로 포커스를 옮깁니다.
- 동작: 시트 열림·펼치기 외 장식 애니메이션 없음. `prefers-reduced-motion`이면 전환 효과를 끕니다.

### 4.5 상태

| 상태 | 규칙 | 기존 문구 |
|---|---|---|
| 로딩 | 목록·카드 모양의 자리 표시(스켈레톤) + `role="status"` 문구. 레이아웃이 밀리지 않게 자리 유지 | — |
| 빈 상태 | 점선 상자 + 제목 + 다음 행동 1개 | "등록된 작품이 없습니다", "아직 평가가 없습니다", 리뷰 없음 |
| 오류 | 빨간 안내 + 원인 + "다시 시도" | "서버에 연결할 수 없습니다…" |
| 저장 결과 | 성공 초록(`role="status"`), 반영 여부 모름 정보색, 로그인 만료 빨간색(`role="alert"`). 결과는 행동한 자리 바로 아래 | 별점·리뷰 기존 안내 문구 그대로 |
| 과부하(#28 후) | 정보색 + `Retry-After` 기반 "약 N초 후" | `AUTH_BUSY` 안내 |

## 6. 접근성·국제화 점검 항목

- 제목·작가 이름에 언어 코드(`lang`)를 지정합니다(현재와 같음). 일본어 대체 글꼴을 둡니다.
- 별은 장식(`aria-hidden`)이고, 스크린 리더는 "평균 별점 5점 만점에 4.6점, 342명 참여"를 읽습니다(현재 문장 유지).
- 별점 선택은 실제 라디오(`fieldset`/`legend`)이고, 시트는 `role="dialog"`·`aria-modal`입니다.
- 색만으로 구분하지 않습니다(스포일러 = 색 + 배지 글자, 저장된 별점 = 테두리 + 문구).
- 대비 기준: 글자 4.5:1, 포커스·경계 3:1 이상(§4.1).
